## 实测发现并修复

OpenList v4.2.6 的原始异步 PUT 在零字节请求上会出现后台 `context canceled`。仅零字节上传改用其官方 multipart 接口，非空文件仍使用原始流式 PUT。

重复打开错误稳定复现于主窗口销毁后触发 `second-instance`：旧窗口引用仍被调用，抛出 `Object has been destroyed`，实际原代码位置为 `main.js:193:62`，与用户截图一致。清除旧引用并对重复启动、延迟显示及退出过程检查窗口状态后，原复现与扩展生命周期回归均通过。

首次并行运行完整集有两项原有队列测试超过 3 秒等待上限；各项功能断言没有改变，改为串行运行相同测试。`npm test` 已固定此调度方式。

合并时复现了分页迁移与退出账号的竞态：延迟的状态查询读取旧凭证，随后可能重建已退出挂载。迁移改到引擎启动阶段并只更新现存记录 ID；`getAccounts()` 保持只读，回归测试验证退出后不再写回账号。

任务恢复按每个文件的持久记录处理。引擎任务表重启后缺失时，先检查已记录目标的文件名和字节数；若目标缺失，重新传输并重新执行重名检查。

## 尚未验证与限制

- 未登录真实夸克或 115 账号，没有声称通过真实云端端到端测试。
- 未实测几十到几百 GB 的实际云端搬运或其账号限速；源码检查与本地测试不保证远端接口持续可用。
- 自动登录的真实授权页面交互仍需本人账号验证。保留手动 Cookie / Token 接入。
- 文件核对采用路径和精确字节数，不是内容哈希校验。
- OpenList 的不覆盖检查不具备跨客户端原子锁；传输时避免其它客户端同时写入同一目标名称。
- 正常成功后的缓存清理已验证。崩溃或强制结束时，底层引擎仍可能留下临时文件，程序不会盲目删除所选缓存目录的其它内容。
